## 一、实施目标

本次实施用于验证真实 MCP 客户端是否能够：

1. 根据工具 description 主动调用本地校园 PDF 知识库；
2. 仅在 `evidence_sufficient=true` 时依据检索证据作答；
3. 在 `evidence_sufficient=false` 时明确拒答，不使用模型记忆、常识或猜测补充结论；
4. 在答案中同时引用 `source_file`、`page` 和 `chunk_id`；
5. 将失败归因到检索、证据判断或答案生成阶段。

本次没有创建 worktree，也没有实施后续计划中的项目复现、定向检索优化和性能改进。

## 四、真实客户端评测链路

新增 `evaluation/run_answer_evaluation.py`，执行流程如下：

```text
读取固定问题集与版本化 Prompt
→ 启动只读、临时 Codex CLI 会话
→ 连接真实本地 STDIO MCP Server
→ 每题调用一次 search_knowledge_base(limit=5)
→ 保存 Codex 原始 JSONL 事件
→ 从原始 MCP 事件提取权威检索结果
→ 合并最终答案、拒答和引用
→ 生成 predictions.json、manifest.json 和自动诊断报告
```

每次运行会保存：

- 原始问题；
- `evidence_sufficient`、`confidence` 和 `reason`；
- 完整检索结果及 chunk ID；
- 最终答案或明确拒答；
- 答案实际引用的 `source_file`、`page` 和 `chunk_id`；
- 客户端、模型、Prompt、description、数据集和代码版本信息；
- 原始客户端事件和错误日志。

运行器不会信任模型复述的检索状态，而是从 Codex JSONL 中的实际 `mcp_tool_call` 结果提取检索证据，再与模型最终答案合并。它还会校验每个问题是否恰好检索一次、是否使用 Top 5、问题和预测 ID 是否完全匹配，以及引用列表与 chunk ID 是否一致。

## 五、答案评估器扩展

`evaluation/evaluate_answers.py` 已扩展以下指标：

- 答案事实覆盖诊断；
- 人工正确率和完整性；
- 引用准确率与引用召回率；
- 答案是否具有受支持引用；
- 引用的文件、页码和 chunk ID 是否完整；
- 错误回答率；
- 错误拒答率；
- `evidence_sufficient=false` 时的拒答遵守率；
- 使用模型记忆或猜测的比例。

人工复核字段固定为：

```json
{
  "correct": null,
  "complete": null,
  "citation_supported": null,
  "uses_model_memory_or_guess": null
}
```

自动字符匹配只作为诊断，最终正确性、完整性和引用支持结论以人工复核为准。

### 失败归因

报告为每题给出一个主要阶段：

| 阶段 | 判定方式 |
| --- | --- |
| `retrieval_error` | 可回答问题的 Top 5 中没有人工标注的相关 chunk |
| `evidence_judgment_error` | 已检索到相关 chunk 却判断证据不足，或不可回答问题被判断为证据充分 |
| `generation_error` | 客户端违反拒答要求、错误拒答、漏引相关证据，或人工复核发现错误、不完整、无证据支持或使用模型记忆 |
| `pending_manual_review` | 检索、证据判断和引用初检通过，等待人工复核 |
| `passed` | 所有自动检查和人工复核均通过 |

因此报告能够区分检索错误、证据判断错误和生成错误，不再只提供一个总分。

## 八、当前阻塞与后续动作

正式运行会把 12 个问题以及 MCP 检索到的本地校园 PDF 证据片段发送给 OpenAI/Codex。由于这些证据来自本地文档，必须先获得明确的数据外发授权。

当前 `evaluation/release_manifest.json` 属于第一优先级开始前的冻结周期。`README.md`、`evaluation/evaluate_answers.py`、`src/mcp_server.py` 和相关测试已经进入新的代码基线，用该历史清单校验当前源码会出现预期的哈希/大小差异。本次不覆盖历史清单，也不把它描述成当前第一优先级的冻结结果；是否创建新发布清单应在真实评测状态确定后另行处理。

同理，现有 `evaluation/reproduction_plan.json` 的 `unit-tests` 步骤仍运行上一周期的 `unittest discover`，不会收集当前全部 pytest 风格测试。本报告的 96 项结果来自单独执行的当前完整 pytest 套件；本次不修改历史复现计划，以免在第一优先级未完成时提前进入第二优先级收口。

此外，`docs/` 已纳入版本控制，当前报告会进入提交并随分支传递；`slides/` 仍被 Git 忽略，不包含在本次提交中。

获得授权后，仅继续第一优先级，按以下顺序完成：

1. 运行 `evaluation/run_answer_evaluation.py` 生成真实预测和原始事件；
2. 逐题人工复核正确性、完整性、引用支持和模型记忆使用情况；
3. 重新运行答案评估器生成带人工复核的最终报告；
4. 将真实指标和失败案例补充到本报告，不开展第二及以后优先级工作。

在正式运行前，不声明答案正确率、引用准确率或拒答遵守率已经达到验收标准。
