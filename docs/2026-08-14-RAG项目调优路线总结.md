## 一、路线概览

项目的调优主线不是反复更换模型，而是按问题所在层级逐步推进：

```text
本地 RAG-MCP 闭环
→ PDF 原生文本/表格与扫描件 OCR
→ 结构化切块和可追溯索引
→ BM25 + 向量 + RRF 混合召回
→ 向量输入、融合权重和查询扩展
→ Cross-Encoder 二阶段重排
→ 扩展评测、独立测试集与拒答诊断
→ 表格检索与 Top-5 非回归保护
→ 证据充分性、原子入库、缓存和可复现发布
→ 真实 MCP 客户端答案级评测
```

整体思路是：先提高输入和召回上限，再改善排序；检索指标稳定后，转向拒答、答案正确性和工程可交付性。

## 二、按时间梳理的调优路线

| 阶段 | 时间与代表提交 | 主要调整 | 简单原因 | 当时或当前结论 |
| --- | --- | --- | --- | --- |
| 1. 建立本地闭环并重整实现 | 07-27 至 07-31；`67b5e16`、`43a7c4a`、`d15436f` | 建立项目结构和本地 RAG-MCP 检索链路，随后清理早期遗留实现重新组织 | 先证明 PDF 能入库、MCP 能查询，再进入可测量的调优；早期实现不适合继续堆功能 | 完成最小闭环，但检索仍以关键词和哈希向量为主，质量上限较低 |
| 2. 先解决 PDF 输入质量 | 08-07；`da7c999`、`9fb4d50` | 原生 PDF 使用文字/表格提取，扫描 PDF 使用 OCR；保存页码、来源和提取产物 | RAG 的上限由可检索文本决定；表格丢结构、扫描件无文本时，换检索算法也找不到证据 | 形成原生与扫描 PDF 两条处理规范，证据可追溯到文件和页码 |
| 3. 切块与索引结构化 | 08-07 至 08-09；`17079dd`、`7a9bea8` | 从早期约 700 字符切块转为 tokenizer 感知切块；当前为目标 410、最大 512、重叠 41 tokens，并为表格生成行级块 | 块太大会混入无关信息，太小会丢上下文；表格整块也不利于精确匹配 | 当前索引保存结构化元数据、稳定 chunk ID 和 768 维向量 |
| 4. 从单路检索升级为混合召回 | 08-08；`77a32bc` | 用 BM25 处理精确词匹配，用 `bge-base-zh-v1.5` 处理语义改写，再用 RRF 融合 | 纯关键词难处理同义改写，纯向量又可能弱化名称、数字和制度术语 | 建立“词法 + 语义”双路候选集，成为后续重排的基础 |
| 5. 数据驱动优化向量与融合 | 08-09 至 08-10；`35ed79a`、`2df5c5f` | 扩充评测集；向量输入只编码正文，查询使用检索指令；RRF 固定为 `k=1`、BM25:Vector=`3:1`，每路取 Top 20 | 标题/路径等噪声会污染向量；校园制度问答中的精确术语更适合由 BM25 主导 | 历史阶段 Vector Recall@5 从 66.67% 提升到 70.00%，Hybrid Recall@5 达 93.33%，MRR@5 从 0.6456 提升到 0.6959 |
| 6. 修复剩余召回失败 | 08-11；`2c9ad2e` | 增加受控查询扩展和扫描件跨页连续性处理，继续对融合参数做消融 | 剩余失败主要来自简称/全称不一致和 OCR 页边界断句，而不是向量模型容量不足 | 当轮 90 个可回答样例的 Hybrid Recall@5 达 98.89%，MRR@5 达 0.7133 |
| 7. 引入二阶段重排 | 08-11；`f0bc951`、`552eae2` | 使用 `bge-reranker-base` 对 20 个混合候选做 Cross-Encoder 重排，并扩充 holdout 评测 | 候选通常已召回正确证据，主要问题变成“正确块没有排到前面” | 当轮开发集 Recall@5/MRR@5 为 100%/0.7976，首次锁定集为 100%/0.8458；排序提升但单次查询增加约 2.7 秒模型开销 |
| 8. 扩展评测并暴露拒答问题 | 08-12；`9a5c9ff` | 建立文档隔离的数据集、精确 chunk qrels、nDCG、候选召回和拒答诊断，并冻结配置后再跑锁定集 | 小数据上的高分可能过拟合；只有 Recall/MRR 无法发现“错误拒答”和“错误回答” | 锁定集上重排 Recall@1 从 0.7625 升至 0.85、MRR@5 从 0.8525 升至 0.9021，但 Recall@5 从 0.975 降至 0.9625；单分数阈值造成 35% 错误拒答，扫描件达到 50%，因此未用于生产 |
| 9. v2 表格与重排非回归优化 | 08-13；`48c99b4` | 表格 BM25 使用无损“字段-值”检索文本，向量和重排仍使用原始证据；重排改为排名归一化分数 `+ 0.16 / hybrid_rank`，并保护高置信和表格 Top 5 候选 | 表格是候选召回的主要缺口；重排器也可能把原本正确的强候选挤出 Top 5 | 40 条全精确 qrel 验收中 Recall@1 从 0.875 升至 0.900，MRR@5 从 0.9333 升至 0.9437，nDCG@5 从 0.9358 升至 0.9416；Recall@5 保持 1.0，Recall@3 从 1.0 小幅降至 0.975，结果按冻结规则通过 |
| 10. 从“指标可用”走向生产就绪 | 08-13 至 08-14；`72d3265` 至 `ac10c62` | 增加多信号证据充分性、CLI/MCP 契约、索引版本与原子切换、缓存/预热、运行时基准、模型/PDF 哈希和完整复现记录 | 生产系统还需要安全拒答、失败不破坏旧索引、可观察性能以及别人能复现结果 | 最终复现：2 份文档、393 页、731 chunks、90 项测试通过；90 个可回答样例错误拒答 1 个，10+20 个不可回答样例错误回答 0 个；非缓存 P50/P95 为 2526/3431 ms，缓存为 1.29/1.50 ms |

## 三、关键取舍及原因

| 取舍 | 结论 | 原因 |
| --- | --- | --- |
| 将标题、路径等信息加入向量正文 | 未采用 | 会给语义向量增加噪声；来源信息继续保留在元数据和 BM25 侧更合适 |
| 继续缩小切块 | 未采用 | 局部精度可能上升，但跨句规则和表格上下文更容易被截断 |
| 将候选数从 20 降到 10/15/16 | 未采用 | 扫描 PDF Recall@5、Recall@1 或 MRR 出现回退，且曾有相关候选位于 Hybrid 第 16 位 |
| 将 batch size 从 16 提到 32 | 未采用 | 质量不变，CPU 时延反而更差 |
| 只用 top reranker 分数做硬拒答 | 未采用 | 锁定集错误拒答率 35%，扫描 PDF 为 50%，泛化不足 |
| 立刻替换更大向量/重排模型或微调 | 暂不做 | 候选覆盖已经较高，主要失败集中在表格结构、证据判断和答案链路，先修数据与策略更直接 |
| OCR 全量使用 300 DPI 重建 | 当前发布复现未采用 | 质量提升有限但耗时明显上升；一次 300 DPI 运行超过 30 分钟，原子事务成功保留了旧索引，最终复现采用 160 DPI |

## 四、当前保留的默认配置

| 模块 | 当前值 |
| --- | --- |
| 切块 | 目标 410、最大 512、重叠 41 tokens |
| 词法检索 | BM25，`k1=1.5`、`b=0.75`；表格使用字段-值检索文本 |
| 向量检索 | `BAAI/bge-base-zh-v1.5`，768 维，编码原始证据文本 |
| 融合 | 每路 Top 20；RRF `k=1`；BM25:Vector=`3:1` |
| 重排 | `BAAI/bge-reranker-base`；候选 20；batch 16 |
| 重排公式 | 排名归一化 Cross-Encoder 分数 `+ 0.16 / hybrid_rank`，随后执行高置信和表格 Top-5 保护 |
| 证据判断 | 综合 top score、score margin、BM25/Vector 一致性、证据多样性与问题类型；不使用单一硬阈值 |
| 运行时 | 懒加载模型、查询缓存 128 项、索引版本目录与 `versions/active` 原子切换 |
