# PDF 扫描件处理规范

> 实现同步日期：2026-08-14。本文描述当前 `src/ingest.py` 与 `src/extraction/scanned_pdf.py` 的真实行为；PP-StructureV3 版面分析和扫描表格结构识别尚未实现。

本规范适用于统一导入入口判定为扫描类型的 PDF。`src/ingest.py` 默认抽样前 3 页，累计字母数字字符少于 50 时把整份文档路由到扫描提取器；也可以通过 `--source-type scanned` 显式指定。该路由是文档级的，同一 PDF 内原生页与扫描页自动混合处理仍未实现。原始 PDF 页始终是核对与引用依据。

## 1. 页面保留

默认将每页以 300 DPI 渲染为 PNG，并保存来源文件、页码、来源哈希、渲染 DPI 和 OCR 原始 JSON。固定发布复现为了控制本机 CPU 成本使用 160 DPI；这只是复现配置，不改变日常导入默认值。渲染图属于处理产物，不直接进入索引。

## 2. OCR 识别

当前实现对整页图片直接运行 PaddleOCR，固定使用 `PP-OCRv6_medium_det` 与 `PP-OCRv6_medium_rec`，CPU 推理，并关闭文档方向分类、文档展平和文字行方向分类。识别框按 y 坐标、再按 x 坐标排序后拼成文本；每页保存识别框、文字和置信度的原始 JSON。

当前没有运行 PP-StructureV3，也没有显式区分 `text`、`table`、`image`、`figure` 或 `chart` 区域。因此图中被 OCR 识别出的文字可能进入页面文本，扫描表格也只保留为按坐标排序的普通 OCR 文字，不能宣称已经恢复可靠行列结构。

## 3. 页面文本与跨页续接

每页所有识别文字合并为一个 `source_type=ocr` 的 Markdown 产物。平均置信度低于 0.85 时写入 `low_confidence=true` 和“自动识别，建议核对原 PDF 第 X 页”。统一导入默认把低置信 OCR 页视为质量门禁失败，不发布新产物和新索引；只有人工复核后显式使用 `--allow-quality-failures` 才能接受风险。

当新页以 1–4 个汉字加冒号开头时，提取器会把上一页末尾最多 32 个非空白字符作为“上页续文”前缀写入当前页产物，用于缓解扫描件小标题跨页断开。该规则只补充可审计的上一页原文，不改写 OCR 内容。

## 4. 已知边界

- 扫描表格没有独立 Markdown 表格、表头重复、行号范围或 `source_type=table`；需要可靠数值关系时必须核对原 PDF。
- 当前阅读顺序只是全页 y/x 排序，复杂多栏、浮动文本和不规则版面可能错序。
- 当前没有方向纠正、页面展平、图表语义提取或扫描件版面区域过滤。
- 已存在 OCR 原始 JSON 时，提取器会复用该结果而不重新加载模型；若改变 DPI 或模型并需要重新 OCR，应使用独立暂存资产或先明确处理旧产物。

## 5. 入库与回答

统一导入先在临时目录完成整份扫描 PDF 的 OCR、质量门禁和索引重建，全部成功后才切换正式产物；失败时保留旧索引。进入知识库的是带来源文件、页码、置信度和处理说明的 OCR 文本块，渲染图与原始 JSON只用于审计和人工核对。低置信内容被明确接受后仍须在回答中提示核对原 PDF 页。
