# PDF 原生内容处理规范

> 实现同步日期：2026-08-14。本文描述当前 `src/ingest.py` 与 `src/extraction/native_pdf.py` 的真实行为，不再引用仓库中不存在的《RAG_MCP_SPEC》。

本规范适用于统一导入入口判定为原生类型的 PDF。`src/ingest.py` 默认只抽样前 3 页，累计字母数字字符不少于 50 时把整份 PDF 路由到原生提取器；也可以通过 `--source-type native` 显式指定。原始 PDF 是权威来源；提取结果保留相对来源路径、页码、来源/内容哈希和导入时间。

当前统一入口是**文档级路由**，不是同一 PDF 内逐页调用两个提取器。原生提取器虽然会为每页计算 `native/ocr` 决策，但被判为 `ocr` 的页面目前只记录在元数据中，不会自动交给扫描提取器生成正文。因此混合型 PDF 仍是已知限制，不能宣称已完成逐页混合提取。

## 1. 原生文字

使用 PyMuPDF 按页读取带坐标的文字块，并计算字母数字字符数、替换字符比例、可用文字块面积、重复行比例和阅读顺序异常。出现以下任一硬条件时，该页在元数据中标为 `ocr`：字母数字字符为 0、替换字符比例大于 15%、可用文字块面积小于页面面积的 1%。短文本、重复行比例大于 30% 和阅读顺序异常只记录为质量提醒。

正文使用 PyMuPDF 的排序结果还原，随后按段落和句末标点切分；当前参数为 `target_tokens=410`、`max_tokens=512`、重叠 41 tokens。正文块使用 `source_type=pdf`。

检测到表格后，正文提取会排除与表格区域重叠至少 50% 的文字块，避免表格文字以扁平顺序重复进入正文。

## 2. 原生表格

先用 PyMuPDF `find_tables` 定位表格并提取。候选的非空单元格密度低于 0.60 时，才尝试 Camelot `lattice`，并且只有空间重叠和综合质量分更好时才替换候选。PyMuPDF 没有找到表格、页面又包含“表 N”线索和重复列起点时，才尝试 Camelot `stream`，并用行列数、密度和单元格长度规则过滤伪表格。

当前原生提取器**没有**把失败表格区域回退到 PaddleOCR 表格结构识别。每张成功提取的表转换为独立 Markdown，使用 `source_type=table`；索引阶段再按连续行拆分超长表格块，每块重复表名和表头，并保留表 ID、页码、行号范围和是否存在超长单行。

- 保存表名（如可获得）、文件路径、页码、表序号、提取方法和质量分。表名只从表格上方 100 pt 内匹配 `表 N` 的独立文字行获取；找不到时使用页码和表序号作为名称。
- 多层表头整理为明确列名；第二行表头缺失父级名称时，继承左侧最近父级名称。正文中的纵向合并单元格向下补齐实际归属。
- 自动提取结果直接进入暂存产物；表格得分低于 0.60 时写入 `low_confidence=true` 和核对提示。当前统一质量门禁不会仅因低置信原生表格阻止发布，调用方仍需保留该提示。
- 无法可靠提取时，记录处理失败原因，不根据残缺文本推断数值或条件。

## 3. 入库与回答

统一导入会先在临时目录完成提取、质量检查和索引重建，成功后才一起替换正式产物；原生表格提取异常会计入 `extraction_failures` 并默认阻止发布，除非显式使用 `--allow-quality-failures`。仅正文和成功提取的表格进入知识库；PDF 内嵌图片、图表和图形不处理。检索结果返回文件名、页码、产物路径、chunk ID 和原文片段；低置信内容保留“自动识别，建议核对原 PDF 第 X 页”的处理说明。
