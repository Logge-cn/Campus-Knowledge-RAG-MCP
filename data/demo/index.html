03 · Ingestion

自动识别 PDF 类型，再进入各自的可审计提取流程

原生 PDF

PyMuPDF 按阅读顺序提取正文；表格先用 PyMuPDF 识别，必要时由 Camelot lattice / stream 补充，并把正文与表格分别保存为 Markdown。

版面指标正文去表格表格规范化质量告警

扫描 PDF

PyMuPDF 逐页渲染，PaddleOCR 使用 PP-OCRv6 检测与识别模型；按坐标重排文本，并记录页级置信度、原始结果和跨页续文。

页面渲染中文 OCR坐标排序置信度门禁
来源：docs/PDF原生内容处理规范.md · docs/PDF扫描件处理规范.md

04 · Modules

源码按“导入、索引、检索、服务”四层分工

INGEST

导入事务

识别文档类型，在临时目录完成提取、质量检查与索引构建，成功后整体切换。

INDEX

证据索引

正文按 410 目标、512 上限与 41 Token 重叠切块；表格仅在行间切分并重复表头。

RETRIEVAL

检索策略

BM25 与 BGE 中文向量并行召回，加权 RRF 融合后由 Cross-Encoder 重排。

SERVICE

服务接口

内存加载本地索引与模型，查询结果使用 128 项 LRU 缓存，并通过 STDIO MCP 暴露。

来源：src/ingest.py · src/retrieval/ · src/mcp_server.py

05 · Retrieval

关键词覆盖、语义覆盖与相关性精排组合工作

BM25 × 3 关键词召回
＋ BGE × 1 语义召回
→ Cross-Encoder 精排

两路各取最多 20 个候选，以 RRF 融合；重排分数与检索先验组合，并保护高置信或表格类 Hybrid Top-5 证据。

20每路候选上限
3 : 1BM25 / Vector 权重
0.16重排中的检索先验
128查询 LRU 缓存
模型：BAAI/bge-base-zh-v1.5 · BAAI/bge-reranker-base；来源：src/retrieval/config.py

09 · MCP service

两个工具构成稳定、可检查的客户端接口

TOOLS

服务入口

  • knowledge_base_status：索引、模型、文档数与新鲜度
  • search_knowledge_base：查询本地知识库，返回最多 1–10 条证据
  • STDIO 传输；默认启动时预热索引与两个本地模型
RESPONSE CONTRACT

证据与判断

  • evidence_sufficient / confidence / reason 明确能否据此回答
  • signals 展示词面覆盖、双通道一致性、来源一致性与时效检查
  • results 保留来源、页码、chunk ID、正文与分数；diagnostics 给出缓存命中和耗时
来源：src/mcp_server.py · src/retrieval/hybrid.py · src/retrieval/evidence.py

11 · Scope

能力边界比功能数量更重要

INPUT

本地校园 PDF

面向受控知识库中的中文原生 PDF、结构化表格与扫描 PDF。

OUTPUT

可引用证据

输出检索证据、来源定位与充分性判断，由 MCP 客户端生成答案。

BOUNDARY

非实时搜索

不覆盖互联网实时信息；证据级指标描述检索能力，不代表答案正确率。

来源：README.md · src/mcp_server.py
